## 跨平台验证

| 环境 | 已通过的操作 |
| --- | --- |
| macOS、Ubuntu、Windows 原生 | Node.js 22.19.0 与 24.x 各运行一次 Pi 和核心测试，共六组。[Pi 验收作业](https://github.com/bei7777/pi-minder/actions/runs/45544373121) |
| macOS、Ubuntu、Windows 原生 | 构建三仓库，独立安装 CLI 和插件，实际启动宿主，执行文件、记忆、提醒功能测试，验证便携包及从 0.1.3 升级。[分发验收作业](https://github.com/bei7777/minder/actions/runs/45544394927) |
| WSL2 Debian 12 | 在 Windows runner 实际启动 WSL2，在 ext4 与 Windows 挂载卷分别验证文件操作、升级前事务撤销及记忆审阅，测试两个方向的跨卷备份与恢复。[WSL2 验收作业](https://github.com/bei7777/minder/actions/runs/45544394927) |
| Apple 芯片 Mac | 从成品应用连接获授权的真实模型，验证工具写入、多轮上下文、流式回复、取消和新建会话。实际操作文件差异视图，整项撤销后逐字节比较；在记忆视图接受提案，核查 Markdown 与 SQLite；在提醒页面保存规则，写入真实文件触发提醒，让草稿出现在对话输入框。 |
| macOS 安装 | 实际挂载 DMG，把应用复制到独立 APFS 卷的 Applications 目录，卸载源映像，再从 Launch Services 启动新副本。验证签名、映像校验值、首次设置、窗口导航和包内 SQLite FTS5 写入与检索。 |

发行前的四系统复验固定到便携包所用的 Pi 和 DSH 提交，发行版源码对应 `04b6bcbd5811eb6b9199c13f497fec8955e063f1`。DSH 测试在各自独立的 profile 中安装 snapshot、memory、firewall，核对归档来源和 SHA-512，执行每个插件的一个实际工具；第四个 profile 同时加载三个插件。[固定源码的分发验收](https://github.com/bei7777/minder/actions/runs/45545259133)

正式终端归档还在 macOS、Ubuntu、Windows 原生和 WSL2 分别安装了一次。四个作业使用与 GitHub Release 相同的归档，核对其 SHA-256 和内含十个包的 SHA-512，以空 npm 缓存和原始锁文件运行 `npm ci`，再使用第二个空缓存离线启动 Minder。四项均通过。[同一份安装包的四系统验收](https://github.com/bei7777/minder/actions/runs/45546598648)

终端版从正式归档独立安装，以七次实际模型请求检查初始化、读取随机测试文件、写入、记忆提案、文件差异及逐字节撤销。桌面验收使用同一个 `dmxapi / deepseek-flash-guan` 服务，首次回答包含 80 个流式文本片段。映像使用 ad-hoc 签名，未经过 Apple 公证。当前提供的架构为 arm64。[终端模型记录](model-acceptance-0.1.4.json) · [桌面模型记录](desktop-model-acceptance-0.1.4.json) · [桌面版说明](../desktop/README.md)
